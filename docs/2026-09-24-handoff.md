## Install it

1. Open Tampermonkey → **Dashboard** → **Utilities** → **Import from file**,
   or drag the file onto a browser tab with Tampermonkey installed.
2. File: `dist/chatgpt.user.js` in this repo.
3. If an older ChatGPT Exporter is already installed, **disable or delete it
   first** — two copies will both try to mount.
4. Reload `https://chatgpt.com/`. The **Export** row appears at the bottom of
   the sidebar; with the sidebar collapsed it becomes an icon in the left rail
   just above Help and your profile picture.

Sanity check in DevTools console:

```
[Exporter] Loaded
[Exporter] Injecting nav (sidebar-panel)     ← or (nav-rail) when collapsed
```

`(floating)` means ChatGPT changed its shell again and the exporter fell back
to its own launcher in the bottom-left corner. It still works; the sidebar
selectors need a look.

## What was wrong

ChatGPT removed `data-testid` from the whole app shell. Three things broke at
once:

1. **Mount** — the profile-button anchor vanished; the chain fell through to
   the Automations item, which now lives in a new 52px icon rail, so the menu
   rendered as an unlabeled 32px icon at the top of that rail.
2. **Exports** — `checkIfConversationStarted()` keyed on
   `[data-testid^="conversation-turn-"]` (now 0 matches), so *every* format
   refused with "Please start a conversation first". This was the real damage.
3. **React #418** — injecting during hydration made React discard the shell
   and destroy the freshly mounted menu.

The API layer was fine and was left alone.

---

## How it works now

Three separate concerns:

- **`src/utils/navMount.ts`** — ordered mount strategies, first match wins:
  legacy profile button → legacy footer → expanded sidebar panel → collapsed
  icon rail → floating launcher on `document.body`.
- **`src/utils/threadDom.ts`** — conversation selectors, current generation
  first, retired second, resolved one generation at a time.
- **`src/main.tsx`** — waits for the DOM to go quiet before the first
  injection, then a `MutationObserver` drives remounting. The old 1s poll is
  now a 5s failsafe.

```bash
# pnpm 8.14.1 is pinned via packageManager. If corepack is unavailable:

pnpm install --frozen-lockfile

pnpm lint

```

`dist/` is tracked upstream, so rebuild and commit it with any source change.

The `pre-push` hook runs `pnpm run test`; it fails if a pnpm other than 8.14.1
is first on `PATH`.

## Verifying against the live site

Live verification used Playwright driving **real Google Chrome** (not bundled
Chromium — headless Chromium trips Cloudflare) with Playwright's automation
flags stripped, plus a Tampermonkey-equivalent harness that runs the actual
built `dist/chatgpt.user.js` with a `GM_*` shim, `unsafeWindow`, and the
`@require` libraries loaded from `node_modules`.

Two things to know if you rebuild that harness:

- Synthetic `MouseEvent` clicks are enough to open the menu, but **Copy Text
  needs a real (trusted) click** or the clipboard write is rejected. Radix's
  `Dialog.Trigger` is the `.row-full` wrapper, not the inner `.menu-item`, and
  it wants a full `pointerdown → mousedown → pointerup → mouseup → click`
  sequence.
- `page.screenshot` needs `animations: 'disabled'`; ChatGPT's sidebar marquee
  animations never settle otherwise.

Repeated `/backend-api/conversations` calls get **429 rate-limited** for
several minutes. The Export All list showing 0 rows during heavy testing is
that, not a bug — the dialog correctly displays "⏳ Rate limited — waiting Ns".

## Next steps / open items

1. **Upstream PR — decided against, 2026-09-25.** Not opened, by choice. The
   branch is nonetheless written to stay upstreamable if that changes:
   legacy selectors retained, no version bump, and the fork-only CI change
   kept on a separate branch. Opening it would require making this fork
   public, since GitHub cannot open a pull request from a private fork.
2. **Repo visibility — staying private, 2026-09-25.** Install from the local
   file rather than a raw URL (see *Install it* above).
3. **Version bump** — deliberately not done. Upstream uses release-please;
   contributor PRs leave the version alone.
4. **Watch `[data-turn-key]`.** If ChatGPT renames it, exports break again the
   same way. It is the single highest-value selector to monitor.
5. **Long-thread PNG limit** — a ~48,900px thread (~150M output pixels)
   crashes the renderer during encode. Pre-existing upstream limitation;
   threads up to ~52,000 output pixels are fine. Worth a size guard with a
   clearer message if it comes up.
