## Harness faults corrected this pass

The old checker was written against the private build and quietly reported
nonsense for upstream. Each of these produced a *false* result before it was
fixed, so they are recorded rather than silently cleaned up:

1. **Mount detection keyed on `data-ce-mount`**, an attribute only the private
   build sets. Upstream measured as "never mounts". Now derived from
   `.ce-nav-trigger` and the container's inline `z-index: 99`, which both builds
   set (`CE_MOUNTS_JS` in `manager.mjs`).
2. **Pass required exactly one mount in the DOM.** Upstream deliberately mounts a
   menu in the expanded sidebar *and* the rail and lets the shell hide one, so
   every case failed. The criterion is now exactly one *rendered* launcher.
3. **`Browser.setWindowBounds` was assumed to work.** On macOS it is advisory and
   is dropped often enough that a case measured the previous case's viewport
   under this case's name. Now verified, retried via a known-good size, and
   reported as `NOT MEASURED` rather than passed or failed on the wrong layout.
4. **Sidebar toggles used `element.click()` on the first matching control.** That
   can be the hidden copy, and at drawer widths a synthetic click does nothing at
   all. Now a trusted CDP click on a rendered control, with the resulting state
   read back.
5. **Escape was sent unconditionally to close the menu.** At drawer widths Escape
   also closes ChatGPT's drawer, so the "narrow, drawer open" case measured
   "narrow, drawer shut". Escape is now sent only when the exporter's menu is
   actually open.

## React #418 — controlled comparison

Same browser, same profile, same window (1440×813 CSS viewport), four cold loads
per condition, each in a brand-new tab, `https://chatgpt.com/`. Exactly one
exporter enabled per run, set and verified through `manager-enable.mjs`.

| Condition | Cold loads | Loads logging React #418 | Loads ending with a usable launcher | Launcher size | Exporter runtime errors |
|---|---|---|---|---|---|
| No exporter | 4 | **0 / 4** | n/a | — | 0 |
| Official upstream v2.36.2 | 4 | **4 / 4** | **4 / 4** | rendered | 0 |
| Reconciled candidate `2.36.2-review.627.8f1284a` | 4 | **4 / 4** | **4 / 4** | 314×46 | 0 |

Message, identical in both exporter conditions:
`Error: Minified React error #418; visit https://react.dev/errors/418?args[]=HTML&args[]=`

**Conclusion.** The warning is caused by the exporter mounting into a tree React
is hydrating — it does not occur without an exporter, and it occurs exactly once
per load with either build. It is **console-only**: in every load the launcher was
present, correctly sized and clickable afterwards, and the menu opened at every
step of the SPA navigation check. There is no user-facing failure for a private
hydration fix to eliminate, so `shellSettle.ts` is **dropped**.

This also disposes of the older, conflicting reading in
`docs/upstream-comparison.md`: the 2.36.1-era claim that the private build avoided
#418 does not hold on 2.36.2, and #418 never had a visible consequence to avoid.
