## The proof

`git diff e2dd598 HEAD -- <product paths>` is **empty** for:

`src/` · `tests/` · `dist/` · `package.json`¹ · `pnpm-lock.yaml` ·
`vitest.config.ts` · `tsconfig.json` · `CHANGELOG.md` ·
`.release-please-manifest.json` · `index.html` · `.npmrc` · `.editorconfig` ·
`.husky/` · `scripts/`

¹ `package.json` differs by exactly one added line, the `build:review` script. Its
`version`, `dependencies` and `devDependencies` are upstream's.

The product was not merged hunk by hunk. Those paths were replaced wholesale from
upstream's released tree, so there is no possibility of a fork hunk surviving
inside an auto-merged file.

And the build reproduces upstream's own artifact:

| | Value |
|---|---|
| `pnpm build` output | `dist/chatgpt.user.js`, 587,764 bytes |
| SHA-256 | `479675436c6f9f1b4fdf9eb2979e103aa01da359e2d3926eb3e43d622a9d098a` |
| Upstream `e2dd598:dist/chatgpt.user.js` | **byte-identical** (`cmp` clean) |

That identity is also the proof that the review-build scaffolding in
`vite.config.ts` is inert: with `REVIEW_BUILD_ID` unset, the config produces
upstream's bytes exactly.

### What is gone, and why it is gone rather than reverted

Upstream refined PR #400 after this fork cherry-picked it — translated
list-load and rate-limit strings, the final `RateLimitError` handling, and a
partial conversation list that stays exportable under a list error. So the
correct operation was to adopt upstream's final tree, not to revert the fork's
commit. The fork's variant is not present in any form.

Also gone, superseded by upstream's own work between 2.36.2 and 2.36.3:

| Fork-side code | Superseded by |
|---|---|
| `src/styles/missing-tailwind.css` and the borrowed-class styling it propped up | `1b309f7` *own the exporter UI styles instead of borrowing ChatGPT's classes* |
| the fork's sidebar row alignment | `87b26a1` *line up the sidebar Export row with ChatGPT's own rows* |
| the fork's toggle styling | `1757ece` *match ChatGPT's switch style for exporter toggles* |
| the fork's `[role="presentation"]` timestamp pass in `main.tsx` | `5208543` *fetch message timestamps only when they are enabled* |
| i18next / react-i18next, Radix dialog, headlessui hover card | `5cc7269` and `03ebb1d` — upstream replaced all four with its own smaller implementations |
| `dist/chatgpt-exporter-review.user.js` (tracked) | dropped: it was a build of the superseded source. `pnpm build:review` still produces it; `.gitignore` now keeps it untracked. |

Earlier private work — `navMount.ts`, `shellSettle.ts`, the placement patch and
the old theme patch — was already dropped at the 2.36.2 reconciliation and is
recorded in [`2.36.2-reconciliation.md`](./2.36.2-reconciliation.md). None of it
is here.

## What this fork is for now

Not a bug fix. Upstream has the fix, in a better form than the fork's.

What remains worth having:

1. **Windows and macOS installers** for a product upstream ships only as a
   userscript, built and verified by
   [`desktop-release.yml`](../.github/workflows/desktop-release.yml).
2. **A real userscript-manager test tier** — Tampermonkey's own matching, grants,
   run-at, storage and update behaviour, which a `GM_*` shim cannot prove.
3. **A reproducible review-build mechanism** for looking at an unreleased tree in
   a real manager without it masquerading as a release.
4. **This evidence trail.**

## Fork posture

- Repository **public**.
- Publishes **desktop packaging releases only** (`desktop-v*` tags). It does not
  tag or release the userscript, and does not publish to GreasyFork.
- `desktop-v2.36.2.1` stays exactly as published — same tag, same assets. It is
  the record of the working v2.36.2 desktop release.
- No further upstream PR is open from this fork.
